# PERT — Product Identity

The project is dependency-driven. Market validation runs in parallel with foundational engineering; feature expansion is blocked until the relevant evidence gates pass.

## Critical path

A Market hypothesis
-> B Prospect dataset
-> C Discovery interviews
-> F Architecture baseline
-> H Tenant/auth foundation
-> I Serialization core
-> K Public verification
-> L Registration/warranty
-> P Shopify connector
-> V Pilot onboarding
-> Z Pilot evaluation / go-no-go

## Parallel validation path

A -> D Smoke-test landing -> E acquisition experiment -> W prospect sequence -> V pilot onboarding

## Trust path

F -> G threat model -> I/K/L -> N abuse signals -> U security hardening -> V

## Growth path

C + D -> W sales assets
P + V -> X App Store listing
E + V -> Y paid acquisition test
V + Y -> Z go/no-go

Issue bodies are the source of truth for exact dependencies. PERT IDs are stable planning identifiers, not release versions.

## Gate policy

- No RMA/helpdesk expansion before V/Z evidence.
- No Amazon connector before Shopify pilot evidence.
- No DPP/compliance claims without a separate legal/compliance workstream.
- No paid scale campaign before activation and retention are measurable.
